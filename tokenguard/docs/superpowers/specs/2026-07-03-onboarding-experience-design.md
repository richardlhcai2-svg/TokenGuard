# TokenGuard Onboarding & Cost-Saving Experience Design

> **Status:** Design Document
> **Date:** 2026-07-03
> **Goal:** Make TokenGuard dead-simple to install, immediately show value after connecting real APIs, and proactively help users save token costs.

**Target user:** Personal developers and small teams using AI APIs (Claude, GPT, Gemini, DeepSeek).

**Architecture:** Hybrid deployment — standalone `tg serve` (no Docker, SQLite storage) for quick start, `tg deploy` (full Docker Compose stack) for team use. Same `pip install tokenguard` package for both modes.

---

## Phase 1: One-Click Installation

Make `pip install tokenguard` + `tg quickstart` the first and only step a user needs.

### Proxy SQLite Integration

- `_save_usage_async` in `proxy/app/proxy.py`: when backend POST fails (or in standalone mode), fall back to local SQLite
- SQLite schema mirrors usage_records table
- `tg stats` reads from SQLite via a simple query API
- `tg deploy` migration: optional SQLite → Postgres data copy

## Phase 2: Immediate Value After Connecting APIs

Once a user connects real API keys, TokenGuard should immediately show **what they're spending** and **how much they could save**.

### Dashboard Enhancements

| Feature | Current | Enhanced |
|---------|---------|----------|
| Summary cards | Static totals | + vs yesterday / vs last week comparison |
| Cost trend | Raw chart | + Projected spend line + budget line |
| Savings estimate | None | 🆕 "Without TG vs With TG" pricing comparison |
| Model table | Static price list | 🆕 Personalized recommendations based on actual usage |

### Savings Estimate

```python
# Backend: Compare actual spend vs hypothetical "without TG" scenario
# For each usage record, calculate what the user would have paid
# if they'd used our recommended model instead
def estimate_savings(records, organization_id):
    savings = 0
    for record in records:
        # What user paid
        actual = record.cost_usd
        # What we'd recommend instead
        recommended_model = get_recommendation(
            record.model_name, record.task_type, record.input_tokens
        )
        alternative_cost = calculate_cost(
            recommended_model, record.input_tokens, record.output_tokens
        )
        savings += actual - alternative_cost
    return savings
```

### Personalized Model Recommendations

Based on actual usage patterns from the database:

- Group requests by task type (code, chat, analysis) using prompt/response length heuristics
- Compare current model cost vs cheaper alternatives for each task type
- Show projected monthly savings for each recommendation

## Phase 3: Smart Cost Saving

### Budget Alert System (Make Existing Alerts Work)

Current alerts CRUD is complete but not triggered. Phase 3 wires it:

| Alert Type | Trigger | Delivery |
|------------|---------|----------|
| Budget % | Monthly spend > 50/80/100% budget | Dashboard + tg stats + (future) email |
| Growth | Month-over-month > 20% | Dashboard warning |
| Context window | Single request > 80% context | Proxy response headers |
| Anomaly | Hourly spend > 3σ avg | tg stats live alert |

### Cost Prediction

- Linear projection based on 7-/30-day trend
- Display on Dashboard as "Projected end-of-month spend"
- Anomaly detection: flag 3x standard deviation spikes

### Model Downgrade Suggestions (Proactive)

Proxy can return savings suggestions in response headers:

```
# When user requests an expensive model for a small prompt:
x-tokenguard-suggestion: Try claude-haiku-4 for this (save $0.0042)
```

## Constraints

1. **No breaking changes to existing Docker Compose stack** — all existing containers, configs, and tests must continue working
2. **Proxy backward compatibility** — existing `_save_usage_async` to backend must remain primary path; SQLite is fallback
3. **API Key security** — keys stored encrypted in `~/.tokenguard/config`, never in plaintext files
4. **Minimal new dependencies** — SQLite via stdlib `sqlite3`, terminal UI via `rich` or built-in formatting
